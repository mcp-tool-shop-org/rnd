# Research and Development seat

This repo is the studio's research library: Markdown entries plus a rebuildable
SQLite index, driven by `python -m rnd`. Read README.md for the format.

## Before answering a research question

1. `python -m rnd search <words>` first. The library may already hold it, and
   the NVIDIA skills catalogue is mirrored here too.
2. `python -m rnd tools` lists the instruments you can use (study-swarm,
   research-os, repo-knowledge, ollama-intern, offrig, engine-room, …) with how
   to invoke each one.

## Filing research

- One entry per topic: `python -m rnd new "<title>" --kind <kind> --field <field>`,
  then fill the sections. Write in your own words; never paste copyrighted text.
- Tag every source with its tier. Pasted AI-search output is `[aggregator]` or
  `[user]`, never `[primary]`; find the primary source if a claim matters.
- Claims start `[unverified]`. Mark `[verified]` only with `(via: …, date)` naming
  what checked it. Verification is proportional (Standing Rule 3): don't run a
  verifier pass by default; check when a claim looks wrong, sources conflict,
  or a decision depends on it.
- Keep "what this is" (Summary, Key points) separate from "what it means for the
  studio" (Studio relevance + `relevance: act | watch | reference`). Research
  from outside the studio's fields is welcome; `reference` is a fine verdict.
- Run `python -m rnd check` before committing; it exits 1 on any error.

## Instruments

A studio tool that research can use gets a file in `instruments/` with
`instrument_status: shipped | planned | retired`, `invoke`, `when` and `where`.
When a repo becomes such a tool, add or update its instrument file in the same
change.

## Hard lines

- Public repo: no home-directory paths, no secrets, and nothing that isn't ours
  to publish. Run the identity scan before pushing.
- `catalogs/*/catalog.json` is generated by `rnd catalog sync`; edit
  `review.json` instead.
- No Ollama Cloud models and no paid verifier seats (Standing Rule 1). Anything
  paid needs the Director's go.
- Tests: `python -m unittest discover -s tests -t .`
