  10
  11  - **PIN_PER_STEP — 2.**
  12    - Every move is made by a script at a pinned rnd commit, and every byte moved carries its SHA-256 in a manifest.
  13    - The datapack format already does this (`rnd-datapack/v1`).
  14  - **ANDON_AUTHORITY — 2.**
  15    - `rnd check` gains the size and tier rules (§4) and exits 1 on a breach, so CI stops a bad commit.
  16    - A migration stops on the first hash mismatch.
  17  - **NAMED_COMPENSATORS — 2.** See the table in §8. Owner: R&D for the rnd side, the Publisher for uploads and repo
  18    settings.
  19  - **DECOMPOSE_BY_SECRETS — 2.** Four parts change for different reasons, and each gets its own home:
  20    - text (entries, designs);

  22    - bulk public data;
  23    - private data.

  25    upload, deleting a local copy. Each is asked contrastively in §9.

  72  ## 2. The problems this solves
  73
  74  1. **Bulk data in the clone grows without bound.** Every run adds megabytes of verdict JSONL to git, forever.
  75  2. **Single copies.** The private gold keys and 20 GB of window receipts exist only on E:, a USB drive. A fault on
  76     that one drive loses the studio's evidence for results already published.
  77  3. **No map of where bytes live.** Finding a run's raw output means knowing which disk, folder and tar it's in.
  78  4. **No machine-readable record of experiments.** A question like "which runs used Muse at Q8_0, and what did they
  79     cost?" means reading prose READMEs.
  80  5. **Duplicated binaries** in the receipts, re-uploaded per window.
  81  6. **The data packs sit in the personal namespace,** while the org rule puts tool data under the org.
  82
  83  ## 3. The design: five tiers, each with one home
  84
  85  Every file belongs to exactly one tier. The tier decides where it lives, how it's backed up, and who may see it.
  86
  87  | Tier | What | Home | Public? | Backed up by |
  88  |---|---|---|---|---|
  89  | **T1 text** | entries, instruments, designs, results write-ups, briefs, code | rnd git | yes | GitHub |
  90  | **T2 small data** | per-experiment data a reader needs to check a result: CSVs, trimmed records, prereg files; each file at most 256 KB, at most 2 MB per experiment | rnd git | yes | GitHub |
  91  | **T3 bulk data** | processed data too big for T2: verdict JSONL, diffs, screens | data packs on Hugging Face, manifest in rnd | private until a publish go | HF + D: |
  92  | **T4 raw** | window outputs: tars, generations, logs, journals, pod receipts | **new repo `rnd-data`** (manifests, small raw files) + D: (the bytes) | never public | D: + an off-site copy (§6) |
  93  | **T5 private** | gold keys, item text, sealed items, blind files | **new private repo `rnd-private`**, or a private folder of `rnd-data` (§9 Q2) | never | GitHub (private) + D: |
  94
  95  - **Not stored at all:** anything rebuilt from a pin. Binaries built from a pinned source (llama-server), and model
  96    weights already hosted. Their pins and SHA-256s go in the manifest; one copy of each build stays in T4, not one per
  97    window.
  98  - **readouts is unchanged.** It stays the shelf of verified knowledge bases. Its 10.8 GB of generated media is
  99    readouts' own matter, listed here only so nobody puts it in rnd-data by accident.

 101  ## 4. rnd itself: conventions that `rnd check` enforces
 102
 103  **The size rule (T2).**
 104  - A tracked file over 256 KB under `experiments/` fails `rnd check`, unless it's listed in a short allow-list with a
 105    reason.
 106  - An experiment over 2 MB in total fails the same way.
 107  - **Existing files are grandfathered** by a list generated once, so nothing turns red on day one.
 108  - **The ratchet:** the allow-list may shrink, never grow, without an R&D review line.
 109
 110  **The experiment layout.** Every new experiment folder gets:
 111  - `README.md`: the design, result and promotion line, as now;
 112  - `experiment.json`: its machine-readable record (below);
 113  - `data/`: T2 only;
 114  - `scripts/`;
 115  - no raw output. A raw file is referenced by its manifest id in rnd-data.
 116
 117  `rnd new-experiment <name>` scaffolds it from the handbook template.
 118
 119  **`experiment.json`** (schema `rnd-experiment/v1`), written by people and checked by `rnd check`:
 120  - **The basics:** name, status (`designing`, `running`, `parked`, `closed`), the design doc, the template used.
 121  - **Runs:** one row per window or session.
 122    - Its id (13w, 14b, …), where it ran (rig, Colab, RunPod), the hardware, the date.
 123    - Its pins: tool commits, model and quant with SHA-256, seed.
 124    - Its cost: units or dollars, measured, with the projection beside it.
 125    - Its outcome: ok, cut or failed, with the reason.
 126    - Its raw manifest id in rnd-data.
 127  - **Ledgers:** the budget, its cap and who set it. The total spent is computed from the runs, never typed.
 128  - **Data:** the T2 files, the data packs (T3) and the raw manifests (T4) it uses.
 129  - **Licences:** the registry ids it relies on.
 130
 131  ## 5. The databases
 132
 133  The text stays the source of truth, and every database is rebuilt from it. That's how `rnd.db` works today, and it
 134  works.
 135
 136  **`rnd.db` gains five tables,** built from `experiment.json` files and data-pack manifests:
 137  - `experiments` (name, status, template, design path);
 138  - `runs` (experiment, id, venue, hardware, date, cost, projected cost, outcome, pins as JSON);
 139  - `ledgers` (experiment, budget, cap, spent: computed);
 140  - `artifacts` (id, tier, sha256, bytes, licence, location: `git:<path>`, `hf:<repo>@<rev>/<path>`,
 141    `data:<manifest>/<path>`, `d:<path>`);
 142  - `uses` (experiment, artifact).
 143
 144  It gains these commands:
 145  - `rnd runs [--model …] [--venue …]`;
 146  - `rnd ledger <experiment>`;
 147  - `rnd where <artifact or path>`: where the bytes are, and every copy.
 148
 149  `rnd sql` already gives read-only SQL.
 150
 151  **rnd-data keeps its own manifest index** (`rnd-data.db`, generated, not in git): every raw file's SHA-256, size,
 152  the window it came from, and each copy's location (D:, off-site).
 153  - `rnd where` reads both databases.
 154
 155  **What doesn't change:** readouts' knowledge-base databases.

 157  ## 6. rnd-data, the new repository
 158
 159  - **Name and owner:** `mcp-tool-shop-org/rnd-data`, private.
 160  - **What's in git:**
 161    - one manifest per window (`windows/<id>/manifest.json`: every file's path, SHA-256, size, tier, licence and
 162      copies);
 163    - raw files under 256 KB that matter: logs, journals, receipts JSON, `outcome.json`;
 164    - a README.
 165  - **What's not in git:**
 166    - the tars, generations and binaries. They live on D: under `D:/rnd-data/windows/<id>/`, with an off-site copy.
 167    - **The off-site copy is an open choice** (§9 Q3): a private Hugging Face dataset repo, or another store. Its
 168      cost and limits are read from the vendor's page before choosing (rung 0). This plan doesn't assume either.
 169  - **Tooling:** `rnd raw ingest <receipts-dir> --window <id>`. It hashes every file and writes the manifest. It copies
 170    to D: and verifies by hash. It drops a file whose SHA-256 is already stored, and records a pointer to it instead.
 171    - It never deletes the source. Deleting the local copy is a separate step after verification, on the Director's
 172      go.
 173  - **Per org standards:** the Atlas map and `atlas check` if it runs workflows; the coverage bar for its code (the
 174    ingest code lives in rnd, so rnd-data may have no code at all); the repo-first rule before any coding.

 204  1. **Tier boundaries.** Is 256 KB a file and 2 MB an experiment the right T2 line? Should a hard cap be by type

 126  ## Entry format
 127
 128  ```markdown
 129  ---
 130  id: 2026-10-07-cuda-graphs        # defaults to the file name
 131  title: CUDA Graphs
 132  date: 2026-10-07
 133  kind: concept                     # finding concept release paper tool catalog rig-fact event question decision instrument
 134  relevance: reference              # act | watch | reference
 135  fields: [gpu-computing]           # any research field, open vocabulary
 136  tags: [cuda-graphs, pytorch]
 137  ---
 138
 139  ## Summary
 140  ## Key points
 141  ## Studio relevance
 142  ## Claims
 143  - [unverified] A checkable statement.
 144  - [verified] A checked statement. (via: what checked it, date)
 145  ## Sources
 146  - [primary] https://… — publisher
 147  ```
 148
 149  - **Source tiers:** `primary` (vendor docs, papers, repos), `secondary`
 150    (reputable write-ups), `aggregator` (summary sites, AI search output),
 151    `user` (supplied by a person: slides, notes), `rig` (measured on our machines).
 152  - **Claim confidence:** `unverified`, `verified`, `disputed`, `wrong`. A
 153    `verified` or `wrong` claim must say what checked it with `(via: …)`.
 154  - `[[entry-id]]` links entries; `rnd show` lists backlinks.
 155
 156  ## Data packs
 157
 158  Processed data too big or too bulky for the clone is offered as a **data pack**: the bytes live
 159  on a Hugging Face dataset repo (private until published), and the library keeps only a small
 160  manifest. The integrity model comes from
 161  [research-packs](https://github.com/mcp-tool-shop-org/research-packs): a manifest, a SHA-256 for
 162  every file, a one-command verify, and a listing.
 163
 164  ```bash
 165  rnd datapack build natural-errors --source experiments/natural-errors  # reads datapacks/natural-errors/spec.json
 166  rnd datapack list
 167  hf download mcp-tool-shop/rnd-natural-errors --repo-type dataset --local-dir ne
 168  rnd datapack verify natural-errors --copy ne/files                      # PASS when every byte matches
 169  ```
 170
 171  - **Every file needs a licence** in the spec. Model outputs carry their model's terms (for
 172    example "Built with Llama" for Llama 3.1 outputs). `rnd datapack build` refuses a pack that
 173    leaves a file uncovered.
 174  - **Every generating model is pinned** (Ollama digest, HF revision or API model id), with its role.
 175  - **`rnd check` validates every manifest** and fails on one edited by hand.
 176  - The upload carries `datapack.json` beside the files, so anyone can verify without this repo:
 177    `pip install mcptoolshop-rnd`.
 178
 179  ## Collected experiment records
 180
 181  A tool repository commits its own pre-registered specs and run records (interlock's receipts),
 182  the way every repository commits its Atlas map. The library publishes only a trimmed copy of the
 183  numbers, made by `rnd collect` from the tool repository at pinned commits:
 184
 185  ```bash
 186  rnd collect                 # list the experiments that collect records
 187  rnd collect e4b             # read each source with git show, trim it, write experiments/e4b/results/
 188  rnd collect e4b --check     # recompute every output; exit 1 if any differs from the committed file
 189  ```
 190
 191  - **`experiments/<name>/collect.json`** names the repository, the sibling clone it's read from
 192    (`--clone` overrides), and each source: its path, the commit, the SHA-256 of its bytes, the
 193    output and the trim function in the experiment's `extract.py`.
 194  - **A pinned source never changes.** Bytes that no longer hash to the pin are refused.
 195  - **Every record carries provenance:** the repository, the source path and the SHA-256 of the
 196    bytes trimmed.
 197  - **Every output is public-safe before it is written.** No machine path, home directory or
 198    environment field survives, and an experiment's module can add a stricter guard. Nothing is
 199    written on any refusal.
