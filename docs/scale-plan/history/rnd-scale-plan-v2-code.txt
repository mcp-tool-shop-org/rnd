  12  ## Standards compliance (workflow standards, 0–3)
  13
  14  - **PIN_PER_STEP — 2.**
  15    - Every move is made by a script at a pinned rnd commit, and every byte moved carries its SHA-256 in a manifest.
  16    - The datapack format already does this (`rnd-datapack/v1`).
  17  - **ANDON_AUTHORITY — 2.**
  18    - `rnd check` gains the size, layout and private-file rules (§4) and exits 1 on a breach, so CI stops a bad
  19      commit.
  20    - A backup or ingest stops on the first hash mismatch.
  21  - **NAMED_COMPENSATORS — 2.** See §8. Owner: R&D for the rnd side, the Publisher for uploads and repo settings.
  22  - **DECOMPOSE_BY_SECRETS — 2.** Text, small public data, bulk public data, raw data and private data change for
  23    different reasons, and each has its own home.
  24  - **UNCERTAINTY_GATED_HUMANS — 2.** The irreversible steps each wait on the Director's go: a new repository, a public
  25    upload, deleting a local copy. Each is asked contrastively in §9.
  26  - **EXTERNAL_VERIFIER — n/a.** No specialized claims. Argon reviews the design as normal practice.

  70  ## 2. The problems this solves
  71
  72  1. **Single copies on one USB drive.** The sealed gold keys, 20 GB of window receipts and the watch's history.
  73     A fault on E: loses the evidence behind published results. **This is the only problem here that can lose data,
  74     so it's solved first (P0).**
  75  2. **Bulk data in the clone grows without bound.** Every run can add megabytes of verdict JSONL to git, forever.
  76  3. **No map of where bytes live.** Finding a run's raw output means knowing which disk, folder and tar it's in.
  77  4. **No machine-readable record of experiments.** A question like "which runs used Muse at Q8_0, and what did they
  78     cost?" means reading prose READMEs.
  79  5. **Duplicated builds** in the receipts.

  81  ## 3. The design: five tiers, each with one home
  82
  83  Every file belongs to exactly one tier. The tier decides where it lives, how it's backed up, and who may see it.
  84
  85  | Tier | What | Home | Public? | Copies |
  86  |---|---|---|---|---|
  87  | **T1 text** | entries, instruments, designs, results write-ups, briefs, code | rnd git | yes | GitHub |
  88  | **T2 small data** | data a reader needs to check a result: CSVs, trimmed collected records, prereg files, small structured inputs | rnd git | yes | GitHub |
  89  | **T3 bulk data** | processed data a reader may want but rnd needn't carry: verdict dumps, diffs, screens | data packs on Hugging Face, manifest in rnd | private until a publish go | HF + D: |
  90  | **T4 raw** | run outputs from any venue (rig, Colab, RunPod): tars, generations, logs, journals, receipts, custom builds | **new private repo `rnd-data`** (manifests + small files in git), bytes on D: and off-site | never | git (manifests) + D: + off-site |
  91  | **T5 private** | sealed gold keys (held-out keys for blind tests), item text, blind files, private project notes, the watch's history | `rnd-data/private/` in git | never | GitHub (private) + D: |
  92
  93  **The content rule** (round 1 Q1): what a file is decides its tier first, and size second.
  94  - **Per-item raw generations, raw verdict dumps and raw run logs** are T3 or T4, whatever their size.
  95  - **Small structured files** stay in T2 under the size limits: a prompt list, a trimmed collected record, a prereg.
  96  - **"Gold" in a public pack** (for example `data/gold.json`, a published benchmark's labels) is T3 and public. Only
  97    **sealed** gold keys, held out for a blind test, are T5.
  98
  99  **Not stored by us:** model weights already hosted upstream. Their pin and SHA-256 go in the manifest.
 100
 101  **Stored once, by content (round 1 F3):** builds we made ourselves, such as llama-server.
 102  - They live once in `D:/rnd-data/blobs/<sha256>/` and off-site.
 103  - Each window's manifest lists them by SHA-256.
 104  - No window points inside another window's folder, so archiving one window can't break another.
 105
 106  **readouts is unchanged.** It stays the shelf of verified knowledge bases. Its 10.8 GB of generated media is
 107  readouts' own matter, listed here only so nobody puts it in rnd-data by accident.

 109  ## 4. rnd itself: conventions that `rnd check` enforces
 110
 111  **The size rule (T2).**
 112  - A tracked file over 256 KB under `experiments/` fails `rnd check`, unless it's on the grandfather list.
 113  - An experiment over 2 MB in total fails the same way.
 114  - **The grandfather list** is generated once from today's files, so nothing turns red on day one. It may shrink,
 115    never grow, without an R&D review line.
 116
 117  **The private-file rule (round 1 F5).** `rnd check` fails on any tracked file that:
 118  - has a SHA-256 listed in `rnd-data/private/manifest.json`, when a local rnd-data checkout is present;
 119  - or matches the private name patterns: `*blind*`, `*sealed*`, `*gold-key*`, `*-items-text*`.
 120
 121  The patterns are the backstop for a machine without rnd-data. A false hit goes on a short, reviewed allow-list.
 122
 123  **The experiment layout** (round 1 F5):
 124  - `README.md`: the design, result and promotion line, as now;
 125  - `experiment.json`: its machine-readable record (below);
 126  - `data/` and `results/`: T2 only (`results/` is where `rnd collect` writes, and `collect.json` stays at the top);
 127  - `scripts/`;
 128  - `staging/`: gitignored, the `--source` for `rnd datapack build`, so bulk files can be built into a pack without
 129    ever being committed.
 130
 131  `rnd new-experiment <name>` scaffolds it from the handbook template.
 132
 133  **`experiment.json`** (schema `rnd-experiment/v1`):
 134  - **Written by people:** name, status (`designing`, `running`, `parked`, `closed`), the design doc, the template
 135    used, budgets, the licences relied on.
 136  - **Written by tools, never typed (round 1 Q5):** the runs.
 137    - The window runner writes `outcome.json` for each run.
 138    - `rnd runs record --from <outcome.json>` adds or updates the run in `experiment.json`: its id, venue, hardware,
 139      date, pins, measured cost, cost unit, projected cost, outcome and raw manifest id.
 140    - It writes no machine paths, the same public-safe rule `rnd collect` already enforces.
 141  - **Budgets:** one per cost unit (`colab_units`, `usd`, `rig_hours`), each with its cap and who set it. Spending is
 142    computed from the runs in that unit, never typed, and never summed across units (round 1 F2).
 143
 144  ## 5. The database
 145
 146  The text stays the source of truth, and the database is rebuilt from it. That's how `rnd.db` works today, and at
 147  thousands of rows a rebuild still takes well under a second.
 148
 149  **`rnd.db` gains five tables:**
 150  - `experiments` (name PK, status, template, design path);
 151  - `runs` (experiment, id, venue, hardware, date, cost, cost_unit, projected_cost, outcome, raw_manifest_id, pins
 152    JSON; PK experiment and id);
 153  - `budgets` (experiment, cost_unit, cap, set_by; spent is computed in the query; PK experiment and cost_unit);
 154  - `files` (sha256 PK, bytes, tier, licence);
 155  - `copies` (sha256, store, location; one row per copy).
 156
 157  **Where the rows come from:**
 158  - `experiment.json` files and data-pack manifests, always;
 159  - `rnd-data`'s window and run manifests, when a local rnd-data checkout is present.
 160
 161  **Machine locations stay out of public rnd.** The `copies` rows for D: and off-site come only from rnd-data's
 162  private manifests, never from anything committed to rnd.
 163
 164  **It gains these commands:**
 165  - `rnd runs [--model …] [--venue …]`;
 166  - `rnd ledger <experiment>`: per cost unit;
 167  - `rnd where <sha256 or path>`: every copy.
 168
 169  `rnd sql` already gives read-only SQL. There is one database, not two (round 1 F7).

 171  ## 6. rnd-data, the new repository
 172
 173  - **Name and owner:** `mcp-tool-shop-org/rnd-data`, private.
 174  - **What's in git:**
 175    - `runs/<id>/manifest.json` for every run from any venue. It lists every file's path, SHA-256, size, tier and
 176      licence, and where each copy is. A `models` list at the top gives every generating model with its pin, licence
 177      and required notice, and each raw file inherits from it (round 1 Q6).
 178    - Raw files under 256 KB that matter: logs, journals, receipts JSON, `outcome.json`.
 179    - `private/`: the T5 files and their manifest.
 180    - A README.
 181  - **What's not in git:**
 182    - large raw files, on D: under `D:/rnd-data/runs/<id>/`;
 183    - custom builds, under `D:/rnd-data/blobs/<sha256>/`;
 184    - and the off-site copy of both.
 185  - **The off-site copy:** chosen at P3 (§7) on four criteria, from the vendor's own pages read at the time (round 1
 186    Q3):
 187    - its file-size and total limits: files reach 159 MB, and the total is 20 GB and growing;
 188    - its monthly cost at 20–100 GB, and the egress cost of a full restore;
 189    - whether upload and restore can be checked against the manifest's SHA-256s;
 190    - a scripted restore test.
 191  - **Tooling, in rnd:**
 192    - `rnd raw ingest <dir> --run <id>`: it hashes every file, writes the manifest, copies to D:, verifies by hash, and
 193      puts custom builds in the blob store. It never deletes the source.
 194    - `rnd raw verify --run <id> [--remote]`: it re-hashes every copy, and with `--remote` it restores one run from
 195      off-site into a temporary folder and checks every SHA-256.
 196  - **Per org standards:** the repo-first rule before any coding. rnd-data holds no code, so the Atlas map and the
 197    coverage bar apply only if it ever gains workflows or code.
