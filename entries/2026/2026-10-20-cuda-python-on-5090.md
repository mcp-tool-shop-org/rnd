## Summary

Six of NVIDIA's CUDA Python libraries were installed, pinned, in a fresh environment on the studio rig: cuda.core,
CuPy, numba-cuda, cuda.compute, nvmath-python and cuTile. Each ran one small kernel on the RTX 5090 (compute
capability 12.0), with its result checked against NumPy on the CPU. All six pass once NumPy is held below 2.5. With
NumPy 2.5, numba-cuda fails. The rung is the experiment `cuda-python-5090-rung`.

## Key points

- **All six run at compute capability 12.0,** on CUDA 13.4 runtime wheels (13.4.92), driver 617.42, Python 3.12.13,
  with exact pins: `cuda-core` 1.2.2, `cupy-cuda13x` 14.2.0, `numba-cuda` 0.30.4, `cuda-cccl` 1.2.1, `nvmath-python`
  1.0.0, `cuda-tile` 1.7.0.
- **cuTile runs on consumer Blackwell**, answering [[2026-10-07-cutile-on-sm120]].
- **numba 0.68.0 calls `numpy.row_stack`,** which NumPy 2.5 removed. A shared GPU environment needs `numpy<2.5` for
  now.
- **CuPy's runtime is its own:** it reports 13.2 (13020) with the 13.4.92 runtime wheel present, and still runs
  correctly.
  - A follow-up on 2026-10-20 listed the process's DLLs. No cudart DLL loads, so the 13.2 runtime is built into CuPy.
  - CuPy does load NVRTC and cuBLASLt from the 13.x wheels, and NVRTC's builtins from the system's 13.4 toolkit.
- **The rung's cost was tiny:** peak VRAM about 340 MiB above idle, under 3 s per library, threads capped at 4.

## Studio relevance

- **This is the installability gate for rnd-data's optional GPU layer:** every candidate library can be built on, on
  this card.
- **The design's `[gpu]` extra pins** these versions and `numpy>=2.4,<2.5`.
- **Next:** which features to build (Argon's exploration, then a design), and a speed rung for the ones chosen. A
  smoke test proves only that a library runs here.

## Claims

- [verified] All six libraries above import, see compute capability 12.0, and run a correct kernel on the RTX 5090 (via: the smoke rung on the studio rig, R&D, 2026-10-19)
- [verified] numba-cuda 0.30.4 with numba 0.68.0 fails on NumPy 2.5.4 (`row_stack`) and passes on NumPy 2.4.6 (via: the same rung, run twice, 2026-10-19)
- [verified] CuPy 14.2.0 uses its own built-in CUDA 13.2 runtime: it reports 13020, and no cudart DLL is loaded in its process, though the env's 13.4 wheel ships cudart64_13.dll. It does load nvrtc64_130_0.dll and cublasLt64_13.dll from the 13.x wheels. (via: scripts/cupy_runtime_check.py in the rung folder, run under the Publisher's grant, R&D, 2026-10-20)
