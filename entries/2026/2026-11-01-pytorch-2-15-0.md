## Summary

PyTorch 2.15.0 is a stable release, dated 2026-10-28. Its main changes:
- The default wheel moves to CUDA 13.2, with a CUDA 13.4 wheel published alongside it.
- `torch.compile` now works on Python 3.15.
- NVFP4 decoding is faster on Blackwell GPUs, through fewer and better-overlapped kernel launches.
- The NCCL backend has been rewritten.
- One change can break code: `import torch` can no longer be run a second time in the same process.

## Key points

- CUDA 13.2 is the default wheel; 13.4 is published alongside it.
- `torch.compile` supports Python 3.15, the studio's current interpreter line.
- NVFP4 decode is faster on Blackwell, which matters for the RTX 5090.
- Breaking change: `importlib.reload(torch)` and other re-imports of torch are no longer supported.

## Studio relevance

`watch`. The studio's GPU environments are on torch 2.14.1 with CUDA 13.0. Python 3.15 compile support and faster NVFP4 on Blackwell are both reasons to try 2.15.0 on a branch environment first.

Before choosing the 13.4 wheel, check whether the open cuBLAS Grouped GEMM bug on Blackwell (the watchlist entry from 2026-11-01) affects the cuBLAS that wheel ships. Until that is known, prefer the 13.2 wheel. Also check whether any harness reloads torch inside one process.

## Claims

- [verified] The 2.15.0 notes list CUDA 13.2 as the default wheel with 13.4 alongside, `torch.compile` on Python 3.15, faster NVFP4 decode on Blackwell via NVGEMM, and the end of re-executing `import torch` in one process. (via: the v2.15.0 release body, read through the GitHub API by the weekly watch, 2026-11-02)
